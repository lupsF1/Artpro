# 分支实现说明：艺考咨询助手（知识库 RAG + 文档入库）

> **分支名**：`艺考咨询助手`  
> **目标**：官网「艺考咨询助手」依据站内知识库 chunk 回答；管理端上传 PDF/Word，解析分块、写入向量（`embedding_json`），对话侧走**混合检索**（稠密相似度 + BM25 + 可选重排）后拼装上下文。  
> **落地状态**：已在仓库实现（`apps/api`、`apps/web`）。环境变量见根目录 [`.env.example`](../../.env.example) 与下文 §2。

## 2. 环境变量（根目录 `.env.example` 已列）

| 变量 | 说明 | 默认 |
|------|------|------|
| `ASSISTANT_RATE_LIMIT` | 公开 `POST /assistant/chat` 限流（slowapi） | `20/minute` |
| `KB_MAX_UPLOAD_MB` | 单文件上传上限 | `10` |
| `EMBEDDING_BASE_URL` | OpenAI 兼容 Embeddings 根 URL；空则使用 `OPENAI_BASE_URL` | 空 |
| `EMBEDDING_MODEL` | 模型 id | `text-embedding-3-small` |
| `EMBEDDING_API_KEY` | 可选；未设时用 `OPENAI_API_KEY` / `MIMO_API_KEY` | 空 |
| `KB_CHUNK_SIZE` | 分块字符上限 | `900` |
| `KB_CHUNK_OVERLAP` | 分块重叠 | `120` |
| `RAG_TOP_K` | 最终送入对话的片段条数 | `5` |
| `RAG_MIN_COSINE` | 稠密路径最低余弦相似度，低于视为未命中 | `0.22` |
| `RAG_DENSE_TOP_K` | 稠密召回池大小（对 `embedding_json` 做余弦） | `30` |
| `RAG_BM25_TOP_K` | BM25 召回池大小 | `30` |
| `RERANKER_BASE_URL` | 可选 Cross-Encoder / rerank API；空则本地轻量重排 | 空 |
| `RERANKER_MODEL` | 重排模型 id（依对接服务而定） | 空 |
| `RERANKER_API_KEY` | 重排服务 Key | 空 |

**说明**：Chat 与 Embeddings 可共用同一兼容网关，也可为 Embeddings 单独设 `EMBEDDING_BASE_URL`（例如网关仅提供 `/v1/chat/completions` 时）。需保证服务端能访问 **`POST {BASE}/embeddings`**（OpenAI 兼容）。

## 3. 数据模型

- **`kb_documents`**：`id` UUID，`title`，`source_type`（默认 `upload`），`source_filename`，`mime_type`，`storage_path`（可选），`status`（`processing`|`ready`|`failed`），`error_message`，`review_status`（`draft`|`approved`，默认 `draft`；**仅 `approved` 参与检索**），时间戳。
- **`kb_chunks`**：`id` UUID，`document_id` FK，`ordinal`，`text`，`meta_json`（页码、`breadcrumb`、`degreeType` 等），`embedding_json`（float 数组的 JSON 字符串）。**当前迁移与 ORM 不包含 pgvector 列**；SQLite 与 PostgreSQL 均用该字段，检索时在应用层对候选集算余弦相似度。

**检索**（`app/services/kb_retrieval.py`）：对已批准文档的 `ready` chunk，先从用户问题推断可选的**元数据过滤**（大纲名、章节、学硕/专硕关键词等），再合并 **稠密 Top-N** 与 **BM25 Top-N** 候选，过滤后 **重排序**，取 `RAG_TOP_K`；稠密分低于 `RAG_MIN_COSINE` 的片段可被丢弃。

**解析与分块**（`kb_chunking.py` / `kb_ingest.py`）：

- DOCX：按顺序读段落、表格等；结构块优先分块；超长块再按字符窗口与 `KB_CHUNK_OVERLAP` 切分。
- PDF：使用 pypdf 等抽取文本；若几乎抽不到文本（多见于扫描件），入库失败并提示需 OCR（**仓库内尚未接入 OCR 管线**，仅错误文案说明）。

## 4. API（`/api/v1`）

### 4.1 公开

- `POST /assistant/chat` — `Content-Type: application/json`，body：`{ "messages": [ { "role": "user"|"assistant", "content": "..." } ] }`（末条须为 `user`）。响应 **SSE**：`delta` / `done`（含 `citations`）/ `error`。需配置 Chat LLM Key 与可用的 Embeddings；知识库无命中时短答并引导 `/contact`。

### 4.2 管理（Bearer，`/admin/kb/...`）

- `POST /admin/kb/documents` — `multipart/form-data`：`file`（`.pdf`、`.docx`），可选 `title`。同步：解析 → 分块 → 批量 Embeddings → 写库；`review_status=draft`。
- `GET /admin/kb/documents` — 分页列表（含 `chunkCount`）。
- `PATCH /admin/kb/documents/{id}` — `review_status`。
- `DELETE /admin/kb/documents/{id}` — 级联删 chunk。

## 5. 后端模块清单（`apps/api`）

1. `app/config.py` — 上述配置项（`Settings`）。
2. `app/services/embeddings.py` — OpenAI 兼容 `embeddings` 批处理与余弦辅助函数。
3. `app/services/kb_chunking.py` — 结构块优先分块与重叠窗口切分。
4. `app/services/kb_ingest.py` — PDF/DOCX 解析与入库状态机。
5. `app/services/kb_retrieval.py` — `retrieve_snippets`：元数据推断 + 稠密 + BM25 + 重排。
6. `app/services/consult_assistant.py` — system 约束 + 流式 Chat。
7. `app/services/llm_openai.py` — `chat_completion_stream_messages`。
8. `app/api/v1/kb_admin.py`、`app/api/v1/assistant.py`；`router.py` 注册；assistant 上使用 `limiter.limit(settings.assistant_rate_limit)`。
9. 测试：`tests/conftest.py` 可抬高限流；`test_assistant_kb.py`、`test_kb_chunking.py`、`test_kb_retrieval.py`。

## 6. 前端（`apps/web`）

1. `lib/consultStream.ts` — `fetch` + SSE 解析。  
2. `components/ConsultAssistant.tsx` — 浮层、流式展示、免责声明、链到 `/contact`。  
3. `app/(site)/layout.tsx` — 挂载 `<ConsultAssistant />`。  
4. `app/(admin)/admin/kb/page.tsx` — 上传、列表、`draft`/`approved`、删除。  
5. `components/AdminNav.tsx` — 「知识库」→ `/admin/kb`。

## 7. 联调

1. 根目录 `.env`：配置 Chat Key；Embeddings 网关可单独设置 `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY`，且能访问 **`/v1/embeddings`**。
2. **PostgreSQL**：`docker compose up -d`（若用 Compose 数据库）后，在 `apps/api` 执行 **`alembic upgrade head`**，确保存在 `kb_documents` / `kb_chunks`。
3. 管理端上传文档 → 将状态改为 **批准** → 官网浮层提问相关内容 → 应看到带引用的回答或「未覆盖」引导。
4. 观察 API 日志中的 `assistant_retrieval` / `assistant_done` / `assistant_error`，核对召回与错误类型。
