# 分支实现说明：艺考咨询助手（知识库 RAG + 文档入库）

> **分支名**：`艺考咨询助手`  
> **目标**：公开站「艺考咨询助手」以向量召回的站内知识库 chunk 为依据回答；管理端上传 PDF/Word，解析分块、写入 embedding（JSON 序列化存储，便于 SQLite 开发；生产大数据量可迁 pgvector）。  
> **落地状态**：已在仓库实现（`apps/api`、`apps/web`）。环境变量见根目录 [`.env.example`](../../.env.example) 与下文 §2。

## 2. 环境变量（追加到根目录 `.env.example`）

| 变量 | 说明 | 默认 |
|------|------|------|
| `ASSISTANT_RATE_LIMIT` | 公开 `POST /assistant/chat` 限流（slowapi） | `20/minute` |
| `KB_MAX_UPLOAD_MB` | 单文件上传上限 | `10` |
| `EMBEDDING_BASE_URL` | OpenAI 兼容 Embeddings 根 URL | 同 `OPENAI_BASE_URL` |
| `EMBEDDING_MODEL` | 模型 id | `text-embedding-3-small` |
| `EMBEDDING_API_KEY` | 可选；未设时用 `OPENAI_API_KEY`/`MIMO_API_KEY` | 空 |
| `KB_CHUNK_SIZE` | 分块字符上限 | `900` |
| `KB_CHUNK_OVERLAP` | 分块重叠 | `120` |
| `RAG_TOP_K` | 召回条数 | `5` |
| `RAG_MIN_COSINE` | 最低余弦相似度，低于视为未命中 | `0.22` |

**说明**：小米 MiMo 是否提供 `/v1/embeddings` 以平台文档为准；若无，可对 Embeddings 单独使用 OpenAI 或其它兼容网关。

## 3. 数据模型

- **`kb_documents`**：`id` UUID，`title`，`source_type`（默认 `upload`），`source_filename`，`mime_type`，`storage_path`（可选），`status`（`processing`|`ready`|`failed`），`error_message`，`review_status`（`draft`|`approved`，默认 `draft`；**仅 `approved` 参与检索**），时间戳。  
- **`kb_chunks`**：`id` UUID，`document_id` FK，`ordinal`，`text`，`meta_json`（页码等），`embedding_json`（float 数组 JSON 字符串，便于 SQLite + 测试 `create_all`）。

检索：对已批准文档的 ready chunk，`embedding_json` 非空；查询向量与各 chunk 做 **Python 端余弦相似度**（体量可控阶段）；后续 Postgres 可换 **pgvector** 列 + IVFFlat/HNSW。

## 4. API（`/api/v1`）

### 4.1 公开

- `POST /assistant/chat` — `Content-Type: application/json`，body：`{ "messages": [ { "role": "user"|"assistant", "content": "..." } ] }`（末条须为 `user`）。响应 **SSE**（与文章流水线一致）：`delta` / `done`（含 `citations`）/ `error`。依赖已配置 Chat LLM Key + Embeddings；知识库无命中时短答并引导 `/contact`。

### 4.2 管理（Bearer，`/admin/kb/...`）

- `POST /admin/kb/documents` — `multipart/form-data`：`file`（`.pdf`、`.docx`），可选 `title`。同步：解析 → 分块 → 批量 `POST .../embeddings` → 写库；`review_status=draft`。  
- `GET /admin/kb/documents` — 分页列表（含 `chunkCount`）。  
- `PATCH /admin/kb/documents/{id}` — `review_status`。  
- `DELETE /admin/kb/documents/{id}` — 级联删 chunk。

## 5. 后端模块清单（`apps/api`）

1. `app/config.py` — 上述配置项。  
2. `app/services/embeddings.py` — OpenAI 兼容 `embeddings` 批处理。  
3. `app/services/kb_chunking.py` — 按字符与重叠切分；可合并 PDF 多页文本。  
4. `app/services/kb_ingest.py` — pypdf / python-docx 解析，异常 → `status=failed`。  
5. `app/services/kb_retrieval.py` — `retrieve_snippets(db, query)`。  
6. `app/services/consult_assistant.py` — system prompt（拒答分数线/包过等）+ 调用 `chat_completion_stream_messages`。  
7. `app/services/llm_openai.py` — `chat_completion_stream_messages(messages, temperature)`。  
8. `app/api/v1/kb_admin.py`、`app/api/v1/assistant.py` — 路由；`router.py` 注册。  
9. `app/api/v1/assistant.py` 使用 `limiter.limit(settings.assistant_rate_limit)`。  
10. `tests/conftest.py` — `ASSISTANT_RATE_LIMIT=10000/minute`。另加 `test_assistant.py` / `test_kb_admin.py`（未登录 401、无 Key 错误帧、mock 嵌入等）。

## 6. 前端（`apps/web`）

1. `lib/consultStream.ts` — 匿名 `fetch` + SSE 解析（可参考 `adminApi.ts` 的 buffer 逻辑）。  
2. `components/ConsultAssistant.tsx` — 浮层 + 流式展示 + 免责声明 + 链到 `/contact`。  
3. `app/(site)/layout.tsx` — 挂载 `<ConsultAssistant />`。  
4. `app/(admin)/admin/kb/page.tsx` — 上传、列表、`draft/approved` 切换、删除。  
5. `components/AdminNav.tsx` — 增加「知识库」链到 `/admin/kb`。

## 7. 联调

1. 配置 Chat + Embedding Key 与 `EMBEDDING_MODEL`。  
2. 管理端上传 PDF → 将文档 **批准** → 官网浮层提问相关句 → 应看到引用型回答或「未覆盖」引导。
